# موقع تجريبي على GitHub Codespaces

هذه نسخة تجريبية كاملة من الموقع تعمل في السحابة: قاعدة بيانات، حجوزات تجريبية، لوحة التحكم، وبوابة دفع **تجريبية** (لا تُخصم أي أموال).

## التشغيل

1. في صفحة المستودع على GitHub: **Code ← Codespaces ← Create codespace on main**.
2. أول مرة يجهّز كل شيء تلقائيًا (٣ إلى ٦ دقائق تقريبًا). تابع التقدم في نافذة الطرفية (Terminal) حتى يظهر `Done.`
3. افتح تبويب **PORTS** واضغط على رابط المنفذ **3000** (Site / الموقع). الرابط يعمل لك أنت فقط لأنه مربوط بحسابك في GitHub.

## الدخول للوحة التحكم

- الرابط: نفس رابط الموقع + `/admin`
- البريد: `admin@example.com`
- كلمة المرور: `Rihla-Test-2026`

## ماذا تجرّب

- **الحجز والدفع:** احجز رحلة، واختر «الدفع عبر ماي فاتورة»، فتفتح صفحة دفع تجريبية فيها زرّا **Pay** (نجاح) و**Decline** (رفض).
- **التحويل البنكي:** مفعّل بحساب تجريبي، وتقدر ترفع صورة إيصال، ثم تؤكده من لوحة التحكم.
- **البوت:** زر المحادثة أسفل الصفحة. اطلب «تكلم مع موظف»، ثم رد عليه من لوحة التحكم ← المحادثات.
- **الخلفية والبنرات:** من لوحة التحكم ← الخلفية والبنرات.
- **السائقين:** لوحة التحكم ← السائقين، ثم افتح حجزًا مدفوعًا واختر السائق. الإرسال التلقائي لواتساب غير مربوط في النسخة التجريبية، فتظهر الرسائل جاهزة بزر «إرسال عبر واتساب».
- **حساب السائق:** ادخل من نافذة خاصة باسم الدخول `0551000001` وكلمة المرور `Rihla-Driver-2026` لترى «رحلاتي».
- **التقييم:** من صفحة حجز مؤكد اضغط «انتهت الرحلة (اطلب التقييم)»، ثم افتح رابط التقييم من رسالة الواتساب الجاهزة، وشاهد التقييم في لوحة التحكم ← التقييمات وفي الصفحة الرئيسية.

## ملاحظات

- الـ Codespace يتوقف تلقائيًا إذا تُرك بدون استخدام (٣٠ دقيقة افتراضيًا)، وعند فتحه من جديد يشتغل الموقع تلقائيًا بنفس البيانات.
- الحساب المجاني في GitHub يعطيك ساعات استخدام شهرية محدودة لـ Codespaces. احذف الـ Codespace من github.com/codespaces إذا انتهيت منه.
- هذه نسخة للتجربة فقط. للتشغيل الفعلي اتبع قسم «النشر على الإنترنت» في README الرئيسي.
- **إذا لم يفتح الموقع:** افتح الطرفية (Terminal) واكتب `bash .devcontainer/start.sh` ثم Enter. ينتظر انتهاء التجهيز إن كان ما زال يعمل، ويصلح ما ينقص (الحزم، جداول قاعدة البيانات، إعادة البناء بعد `git pull`)، ثم يشغّل الموقع ويطبع رابطه. إذا بقيت مشكلة يرسل تقرير تشخيص تلقائيًا (بدون كلمات المرور) إلى فرع `diagnostics` في المستودع ليطّلع عليه المطوّر.
