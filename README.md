# رحلة للنقل: نظام حجز سيارات النقل في المملكة

[![افتح موقعًا تجريبيًا في GitHub Codespaces](https://github.com/codespaces/badge.svg)](https://codespaces.new/Saud1030/rihla?quickstart=1)

نظام كامل لحجز رحلات التوصيل: موقع للعملاء بالعربي والإنجليزي، لوحة تحكم، قاعدة بيانات PostgreSQL، وطريقتا دفع فقط: **ماي فاتورة (MyFatoorah)** أو **التحويل البنكي** الذي تؤكده أنت من لوحة التحكم.

> الاسم «رحلة للنقل» مؤقت. غيّره مع الشعار والألوان والخط من لوحة التحكم ← المظهر والشعار.

## ماذا يوجد في النظام

**موقع العملاء** (`/ar` و `/en`)
- الصفحة الرئيسية: لوحة خضراء فيها تبويب «توصيل» وتبويب «بالساعة مع سائق»، وكلاهما فيه «من» و«إلى» (مع زر تبديل) والتاريخ والوقت، والحجز بالساعة فيه أيضًا المدة (٦ أو ١٢ أو ٢٤ ساعة) تُختار من قائمة مثل الوجهة. الاختيار باللمس بدون كتابة (المنطقة ← المدينة ← المكان) من أكثر من ١٠٠ وجهة في كل مناطق المملكة، ولا شيء مختار مسبقًا. في الحجز بالساعة يظهر وقت الانتهاء تلقائيًا (مثلًا ٦ م + ٦ ساعات = ١٢ ص). وتحتها السيارات حسب عدد الركاب.
- الرحلات والأسعار: نفس لوحة الاختيار (من / إلى أو بالساعة، مع التاريخ والوقت)، ثم تظهر أسعار كل السيارات.
- الحجز بالساعة: سيارة مع سائق ٦ أو ١٢ أو ٢٤ ساعة من أي وجهة، بسعر لكل سيارة.
- رحلة إلى أي مكان: أي وجهتين ليس بينهما سعر ثابت تُسعَّر تلقائيًا حسب المسافة وأسعار كل سيارة.
- ضريبة القيمة المضافة ١٥٪ تُضاف عند الدفع وتظهر مفصّلة (سعر الرحلة + الضريبة = الإجمالي) مع الرقم الضريبي.
- صفحة الرحلة: اختيار السيارة، الاتجاه (ذهاب أو عودة بنفس السعر)، نموذج الحجز بالتاريخ والوقت المختارين مسبقًا، ووقت الانتهاء (بالساعة) أو الوصول المتوقع (التوصيل) محسوبًا تلقائيًا ومحفوظًا مع الحجز.
- الدفع: خياران فقط: ماي فاتورة (ينتقل العميل لصفحة الدفع ويعود تلقائيًا)، أو التحويل البنكي (تظهر له بيانات الحساب والآيبان مع زر نسخ، ويرفع صورة الإيصال أو ملف PDF في صفحة حجزه).
- بوت الاستفسارات: زر محادثة في كل الصفحات، يجيب من أسئلة تكتبها أنت، ويحوّل العميل لموظف يرد عليه من لوحة التحكم (أو لواتساب، حسب إعدادك).
- خلفية أعلى الصفحة الرئيسية: صورة خلف لوحة الحجز والعنوان، ترفعها من لوحة التحكم.
- بنرات العروض تحت لوحة الحجز: تضيفها من لوحة التحكم، وتتبدّل تلقائيًا إذا كانت أكثر من واحد.
- صفحة الحجز: حالة الحجز ونتيجة الدفع، والبحث برقم الحجز، وإلغاء الحجز المدفوع بعد إدخال رقم الجوال المستخدم في الحجز، مع حالة الاسترداد.
- تواصل معنا: واتساب، هاتف، بريد، عنوان، ونموذج رسالة يفتح واتساب جاهزًا.
- الشريط العلوي: الرئيسية، الرحلات والأسعار، السيارات، حجزي، تواصل معنا.
- السيارات، الشروط والأحكام، صفحة 404، زر واتساب عائم، شريط تنبيه قابل للتعديل.
- رقم الواتساب إجباري في نموذج الحجز ويُحفظ بصيغة دولية (يقبل 05xxxxxxxx والأرقام العربية).
- بعد إسناد السائق تظهر للعميل في صفحة حجزه بطاقة «سائقك»: الصورة، الاسم، السيارة والموديل واللون، رقم اللوحة، وزرّا واتساب واتصال.
- صفحة التقييم (رابط خاص يصل العميل على واتساب بعد انتهاء الرحلة): نجوم للسائق ونجوم للشركة وتعليق.
- «آراء عملائنا» في الصفحة الرئيسية: متوسط التقييم وعدده وتوزيع النجوم، وأحدث التعليقات مع الاسم الأول للعميل فقط.

**لوحة التحكم** (`/admin`)
- الرئيسية: حجوزات تحتاج تأكيد سائق، تحويلات بنكية بانتظار التأكيد (وكم منها رُفع إيصاله)، محادثات تنتظر ردك، استردادات بانتظار موافقتك، رحلات اليوم، إيراد الشهر، الرحلات القادمة.
- المحادثات والبوت: صندوق المحادثات مع الرد على العملاء مباشرة، وإعدادات البوت (الاسم، رسالة الترحيب، الرد البديل، طريقة التحويل للموظف) والأسئلة والإجابات.
- الخلفية والبنرات: رفع خلفية أعلى الصفحة الرئيسية أو استبدالها أو إخفاؤها أو حذفها مع اختيار قوة الطبقة فوقها، وإظهار أو إخفاء قسم العروض كاملًا، وإضافة وتعديل وإخفاء وحذف كل بنر مع رابط وتاريخ بداية ونهاية اختياريين.
- السائقين: الاسم، الجوال (واتساب)، رقم اللوحة، نوع السيارة، الموديل، اللون، الصورة الشخصية، وتقييم كل سائق وعدد رحلاته. داخل لوحة التحكم فقط.
- إسناد السائق من صفحة الحجز: تصل للسائق بيانات العميل وللعميل بيانات السائق على واتساب تلقائيًا، ثم «انتهت الرحلة» تُرسل للعميل رابط التقييم. الرحلات التي لم يضغط أحد «انتهت» تنتهي وحدها بعد ٣ ساعات من موعد انتهائها ويُطلب تقييمها.
- التقييمات: متوسط الشركة والسائقين، ترتيب السائقين، كل تقييم مع تعليقه، وإخفاء أي تقييم من الموقع أو إخفاء القسم كله. كل تقييم جديد يصل لبريد الشركة.
- رسائل واتساب والبريد: كل رسالة أُرسلت أو تنتظر مع حالتها، وزر «إرسال عبر واتساب» يفتحها جاهزة إذا لم يكن الإرسال التلقائي مربوطًا، وإعدادات القوالب.
- المستخدمين والصلاحيات: موظفون تختار لكل واحد الأقسام التي يدخلها، وحسابات للسائقين يدخلون برقم الجوال ويرون «رحلاتي» فقط (بدأت الرحلة / انتهت الرحلة).
- الحجوزات: بحث وفلترة بالحالة والتاريخ، تفاصيل الحجز، سجل المدفوعات، تغيير الحالة، ملاحظة داخلية، مراسلة العميل على واتساب، تأكيد استلام التحويل البنكي، إلغاء الحجز مع تحديد مبلغ الاسترداد، والموافقة على الاستردادات.
- الأسعار: جدول واحد لكل الرحلات × كل السيارات، مع سعر «قبل الخصم».
- الوجهات والمدن: إضافة وتعديل أي وجهة (مطار، محطة، فندق، معلم، مسجد…) بلصق رابط خرائط جوجل، وإخفاء أو إظهار أو حذف وجهة بزر في صفها، أو عدة وجهات مرة واحدة بالتحديد، مع فلتر «ظاهرة / مخفية»، وإضافة مدن، وإخفاء مدينة كاملة.
- الرحلات الثابتة، والسيارات (مع أسعار التسعير بالمسافة وأسعار ٦ و١٢ و٢٤ ساعة لكل سيارة).
- المظهر والشعار: رفع الشعار، اسم الشركة، ألوان جاهزة أو مخصصة، الخط، شكل الزوايا، ونص الواجهة، مع معاينة مباشرة.
- الإعدادات والضريبة: نسبة الضريبة، الرقم الضريبي، عرض الأسعار شاملة الضريبة أو لا، تشغيل التسعير بالمسافة، تشغيل الحجز بالساعة، سياسة الإلغاء، الاسترداد التلقائي، بيانات التحويل البنكي (البنك، اسم الحساب، الآيبان)، أرقام التواصل، كلمة المرور.

## التشغيل على جهازك

المتطلبات: Node.js 20.9 أو أحدث، و PostgreSQL 14 أو أحدث.

```bash
npm install
cp .env.example .env        # ثم عدّل القيم داخل الملف
npm run db:migrate          # إنشاء الجداول
npm run db:seed             # بيانات أولية: ١٣ منطقة، ٤٨ مدينة، ١١٠ وجهة، ٨ سيارات، ١٠ رحلات ثابتة، وحساب المدير
npm run dev
```

- الموقع: http://localhost:3000
- لوحة التحكم: http://localhost:3000/admin (البريد وكلمة المرور من `ADMIN_EMAIL` و `ADMIN_PASSWORD`)

> غيّر كلمة مرور المدير من صفحة الإعدادات بعد أول دخول.

### متغيرات البيئة (`.env`)

| المتغير | الوصف |
|---|---|
| `DATABASE_URL` | رابط قاعدة البيانات |
| `NEXT_PUBLIC_SITE_URL` | رابط موقعك، مثل `https://example.com`. ماي فاتورة تُرجع العميل لهذا الرابط بعد الدفع، فلازم يكون رابطًا عامًا (لا تقبل localhost) |
| `AUTH_SECRET` | نص عشوائي طويل (٣٢ حرفًا أو أكثر). أنشئه بـ `openssl rand -hex 32` |
| `ADMIN_EMAIL` / `ADMIN_PASSWORD` | أول حساب مدير (يُنشأ عند `db:seed`) |
| `MYFATOORAH_API_KEY` | مفتاح API من بوابة ماي فاتورة. يبقى على الخادم ولا يصل للمتصفح أبدًا |
| `MYFATOORAH_API_BASE` | للاختبار `https://apitest.myfatoorah.com`، وللتشغيل الفعلي في السعودية `https://api-sa.myfatoorah.com` |
| `MYFATOORAH_WEBHOOK_SECRET` | المفتاح السري للـ Webhook من بوابة ماي فاتورة |
| `WHATSAPP_TOKEN` / `WHATSAPP_PHONE_NUMBER_ID` | واتساب للأعمال (Cloud API من Meta) لإرسال رسائل السائق والعميل والتقييم تلقائيًا. بدونهما تبقى الرسائل في لوحة التحكم بزر «إرسال عبر واتساب» |
| `SMTP_HOST` / `SMTP_PORT` / `SMTP_USER` / `SMTP_PASS` / `SMTP_FROM` | بريد الإرسال (مثل Google Workspace أو Zoho) لإرسال التقييمات لبريد الشركة |

## الوجهات والتسعير

**المناطق والمدن والوجهات** موجودة في `scripts/data/saudi-places.ts`: كل مناطق المملكة الـ١٣، والمدن الرئيسية، والمطارات، ومحطات قطار الحرمين، والمشاعر والمساجد، وأبرز المعالم. الإحداثيات تقريبية (بدقة بضعة كيلومترات) وتُستخدم فقط لحساب المسافة. راجعها وعدّل أو أضف ما تريد من لوحة التحكم.

**كيف يُحسب السعر:**
1. إذا كانت هناك رحلة بسعر ثابت بين الوجهتين (في الاتجاهين)، يُستخدم سعرها.
2. وإلا يُحسب حسب المسافة: المسافة على الطريق ≈ المسافة المباشرة × ١٫٢٥، والسعر = رسوم البداية + سعر الكيلومتر × المسافة، ولا يقل عن الحد الأدنى، ويُقرّب لأعلى ٥ ريال. الأسعار لكل سيارة تُضبط من صفحة السيارات.
3. تُضاف ضريبة القيمة المضافة على الناتج.

كل الحسابات تتم في الخادم، فلا يمكن للعميل تغيير السعر من المتصفح.

## ضريبة القيمة المضافة

- كل الأسعار في لوحة التحكم تُكتب **قبل الضريبة**. الضريبة (١٥٪ افتراضيًا) تُضاف عند الحجز وتُحفظ مع كل حجز: سعر الرحلة، النسبة، مبلغ الضريبة، والإجمالي.
- تغيير النسبة لا يغيّر الحجوزات السابقة.
- فاتورة ماي فاتورة تحتوي سطرين: الرحلة، ثم الضريبة.
- في الإعدادات خيار «عرض الأسعار شاملة الضريبة» في صفحات الموقع. **راجع مع محاسبك** أي طريقة عرض مطلوبة لنشاطك.
- **ملاحظة:** النظام يعرض تفصيل الضريبة والرقم الضريبي، لكنه لا يُصدر فاتورة إلكترونية متوافقة مع متطلبات «فاتورة» من هيئة الزكاة والضريبة والجمارك. إذا كان نشاطك ملزمًا بها، تحتاج ربطًا مع نظام فوترة معتمد.

## التحويل البنكي

1. لوحة التحكم ← الإعدادات ← «طرق الدفع»: اكتب اسم البنك، اسم صاحب الحساب، والآيبان (SA + ٢٢ رقمًا)، وفعّل التحويل البنكي. بدون هذه البيانات لا يظهر الخيار للعميل.
2. العميل يختار «سأدفع بالتحويل البنكي»، فتظهر له بيانات الحساب والمبلغ ورقم الحجز ليكتبه في ملاحظة التحويل، ثم يرفع صورة الإيصال (PNG أو JPG أو WEBP أو PDF، حتى ٥ ميجابايت) في صفحة حجزه.
3. يظهر لك في الرئيسية «تحويلات بنكية بانتظار التأكيد». افتح الحجز لترى الإيصال، وبعد وصول المبلغ لحسابك اضغط «تأكيد استلام التحويل»، فيصبح الحجز مدفوعًا.
   - الإيصالات خاصة: لا يفتحها إلا المدير المسجّل دخوله، ويُفحص كل ملف من محتواه (صورة أو PDF فقط)، وبحد أقصى ٥ إيصالات للحجز.
4. إذا ألغى العميل حجزًا مدفوعًا بالتحويل، لا يمر الاسترداد عبر ماي فاتورة: تحوّل له المبلغ من حسابك ثم تضغط «تم الاسترداد يدويًا».

## بوت الاستفسارات والمحادثة مع الموظف

- لوحة التحكم ← «المحادثات والبوت» ← «إعدادات البوت والأسئلة»: تشغيل البوت أو إيقافه، اسمه، رسالة الترحيب، الرد عندما لا يجد إجابة، ورسالة التحويل للموظف (بالعربي والإنجليزي).
- **الأسئلة والإجابات:** تظهر كأزرار في البوت. وإذا كتب العميل سؤالًا، يبحث البوت في الأسئلة والكلمات المفتاحية ويرد بأقرب إجابة، وإلا يعرض الرد البديل. في الإجابة اكتب `{cancel_hours}` و`{cancel_percent}` و`{phone}` لتُملأ من الإعدادات تلقائيًا.
- **«تكلم مع موظف»:** اختر بين: داخل الموقع + واتساب (الافتراضي)، داخل الموقع فقط، واتساب فقط، أو بدون موظف.
  - داخل الموقع: يكتب العميل اسمه وجواله (ورقم الحجز إن وجد)، وتظهر المحادثة في «المحادثات» مع علامة «تحتاج رد». تكتب الرد فيصل للعميل خلال ثوانٍ. الصفحة تتحدث تلقائيًا.
  - العميل يرى «خدمة العملاء»، ولا يظهر له اسم الموظف.
  - «إنهاء المحادثة» يعيد العميل للبوت إذا كتب من جديد.
- عند إيقاف البوت يرجع زر واتساب العائم كما كان.
- المحادثة مربوطة بكوكي سرّي في متصفح العميل (تُحفظ في قاعدة البيانات بصيغة مشفّرة)، فلا يستطيع أحد قراءة محادثة غيره.

## خلفية أعلى الصفحة الرئيسية

- لوحة التحكم ← «الخلفية والبنرات» ← «خلفية أعلى الصفحة الرئيسية»: ارفع صورة (PNG أو JPG أو WEBP حتى ٣ ميجابايت، المقاس المقترح ١٩٢٠×٩٠٠). تظهر خلف لوحة الحجز والعنوان فقط، وباقي الصفحة كما هو.
- فوق الصورة طبقة فاتحة حتى يبقى العنوان واضحًا: اختر «خفيفة» أو «متوسطة» أو «قوية» حسب الصورة.
- «إظهار الخلفية» يخفيها مؤقتًا بدون حذفها، و«حذف الخلفية» يحذفها نهائيًا.

## البنرات

- لوحة التحكم ← «البنرات» ← إضافة بنر: صورة (PNG أو JPG أو WEBP حتى ٢ ميجابايت، المقاس المقترح ١٦٠٠×٥٠٠)، وعنوان ونص قصير اختياريين، ورابط اختياري (صفحة في موقعك مثل `/ar/routes` أو رابط `https://`)، وتاريخ بداية ونهاية اختياريين، وترتيب.
- تظهر تحت لوحة الحجز في الصفحة الرئيسية. إذا كان هناك أكثر من بنر تتبدّل كل ٦ ثوانٍ، مع أزرار للتنقل.
- إذا لم يكن هناك بنر ظاهر، لا يظهر القسم أصلًا.
- «إظهار قسم البنرات» في نفس الصفحة يخفي القسم كاملًا مرة واحدة، وتبقى البنرات محفوظة.

## السائقين وواتساب والتقييم

1. أضف سائقيك من لوحة التحكم ← السائقين.
2. في صفحة أي حجز مدفوع اختر السائق واضغط «إسناد وإرسال الرسائل».
3. بعد الرحلة يضغط السائق «انتهت الرحلة» من حسابه (أو تضغطها أنت من صفحة الحجز)، فيصل العميل رابط التقييم.

**ربط واتساب للإرسال التلقائي:** أنشئ تطبيقًا في Meta for Developers وفعّل WhatsApp Cloud API برقم شركتك، ثم ضع `WHATSAPP_TOKEN` (توكن دائم لمستخدم نظام) و`WHATSAPP_PHONE_NUMBER_ID` في `.env`. واتساب لا يسمح ببدء محادثة إلا بقالب معتمد، فأنشئ القوالب الثلاثة المقترحة في لوحة التحكم ← رسائل واتساب والبريد ← قوالب واتساب، واكتب أسماءها هناك.

**حساب للسائق:** لوحة التحكم ← المستخدمين والصلاحيات ← نوع الحساب «سائق»، واسم الدخول رقم جواله.

## الحجز بالساعة

- العميل يختار تبويب «بالساعة مع سائق»، ثم «من» و«إلى» والمدة (٦ أو ١٢ أو ٢٤ ساعة) والتاريخ والوقت، كلها في الصفحة الرئيسية. الوجهة تُحفظ مع الحجز وتظهر في عنوانه، والسعر حسب المدة والسيارة.
- السعر لكل سيارة يُضبط من صفحة السيارات (افتراضيًا للسيدان: ٣٥٠ / ٦٠٠ / ١٠٠٠ ريال قبل الضريبة).
- يمكن إيقاف الحجز بالساعة كله من الإعدادات.

## الإلغاء والاسترداد

- **العميل:** من صفحة حجزه، بعد الدفع وقبل موعد الاستلام. يكتب رقم الجوال المستخدم في الحجز (لأن رقم الحجز وحده يفتح الصفحة). بعد ٥ محاولات خاطئة يُقفل الإلغاء لهذا الحجز ١٥ دقيقة.
- **المبلغ حسب السياسة في الإعدادات:** استرداد كامل إذا ألغى قبل الموعد بـ٢٤ ساعة أو أكثر، و٥٠٪ إذا ألغى بعد ذلك (الرقمان قابلان للتعديل). الشروط والأحكام تتحدث تلقائيًا بنفس الأرقام.
- **الموافقة:** افتراضيًا يظهر الاسترداد في لوحة التحكم «بانتظار موافقتك»، وتضغط «موافقة وإرسال الاسترداد». يمكنك تفعيل «إرسال الاسترداد تلقائيًا» من الإعدادات.
- **المدير:** يقدر يلغي أي حجز مدفوع ويحدد مبلغ الاسترداد بنفسه (من صفر إلى المبلغ كامل)، أو يسجّل أن الاسترداد تم يدويًا.
- **ماي فاتورة:** الاسترداد يُرسل عبر `MakeRefund`، ثم يراجعه فريق ماي فاتورة المالي قبل أن يعود المبلغ للبطاقة. لذلك يُسجَّل في النظام «أُرسل إلى ماي فاتورة» مع رقم المرجع، وليس «تم الاسترداد». تأكد أن رصيد حسابك في ماي فاتورة يغطي الاستردادات.

## الشعار والتصميم

من لوحة التحكم ← المظهر والشعار:
- **الشعار:** PNG أو JPG أو WEBP أو SVG حتى ١ ميجابايت. يُحفظ في قاعدة البيانات (فلا يضيع عند إعادة النشر)، ويظهر في الهيدر وأيقونة المتصفح. ملفات SVG التي تحتوي نصوصًا برمجية تُرفض.
- **الألوان:** ٦ مجموعات جاهزة أو ألوان مخصصة، مع تنبيه إذا كان اللون يجعل النص صعب القراءة.
- **الخط:** ريدكس، تجوال، القاهرة، المراعي، نوتو كوفي، أو بلكس.
- **الزوايا:** حادة، متوسطة، أو دائرية.
- **اسم الشركة ونص الواجهة** بالعربي والإنجليزي.

## إعداد بوابة الدفع ماي فاتورة

1. سجّل في [myfatoorah.com](https://www.myfatoorah.com) بحساب **سعودي** (عملة الحساب ريال)، وأكمل التوثيق بالسجل التجاري والحساب البنكي.
2. **للتجربة أولًا:** استخدم بيئة الاختبار `https://apitest.myfatoorah.com` بمفتاح الاختبار من توثيق ماي فاتورة، وجرّب بالبطاقات التجريبية الموجودة في توثيقهم.
3. **مفتاح التشغيل الفعلي:** من البوابة ← Integration Settings ← API Key ← Create، وانسخه إلى `MYFATOORAH_API_KEY`، وغيّر `MYFATOORAH_API_BASE` إلى `https://api-sa.myfatoorah.com`.
4. **الـ Webhook:** من البوابة ← Integration Settings ← Webhook:
   - الرابط: `https://موقعك/api/payments/webhook`
   - الإصدار: **V2**، وفعّل حدث تغيّر حالة الدفع (Payment Status Changed)
   - انسخ الـ Secret Key إلى `MYFATOORAH_WEBHOOK_SECRET`
5. الطرق التي تظهر داخل صفحة ماي فاتورة (بطاقات، محافظ…) تتحكم بها من حسابك في ماي فاتورة. موقعك يعرض للعميل خيارين فقط: «ماي فاتورة» و«التحويل البنكي».

> ماي فاتورة لا تقبل `localhost` كرابط رجوع. لتجربة الدفع الحقيقي من جهازك استخدم رابطًا عامًا مؤقتًا (مثل ngrok أو Cloudflare Tunnel) وضعه في `NEXT_PUBLIC_SITE_URL`.

### كيف يعمل الدفع وما الذي يحميه

```
العميل ← نموذج الحجز ← (الخادم يحسب السعر من قاعدة البيانات) ← صفحة الدفع عندنا
       ← زر «ادفع» ← الخادم ينشئ فاتورة في ماي فاتورة (المبلغ + رقم الحجز)
       ← صفحة ماي فاتورة ← /api/payments/callback?paymentId=...
                                    ↓
          الخادم يسأل ماي فاتورة (GetPaymentStatus) بالمفتاح السري ويتحقق من:
          الفاتورة Paid، وجود عملية ناجحة، المبلغ = مبلغ الحجز بالضبط، ورقم الحجز
                                    ↓
                         الحجز ← «تم الدفع»
```

- **السعر لا يأتي من المتصفح أبدًا.** يُحسب في الخادم ويُرسل لماي فاتورة من الخادم، ثم يُطابق مع مبلغ الفاتورة الفعلي.
- **لا شيء في الرابط موثوق** إلا رقم العملية، والنظام يسأل ماي فاتورة عنه مباشرة.
- **العملية الواحدة تدفع حجزًا واحدًا فقط**، وفاتورة حجز لا يمكن أن تؤكد حجزًا آخر.
- **الـ Webhook موقّع (HMAC-SHA256)** ويُرفض أي إشعار بتوقيع خاطئ. وحتى مع توقيع صحيح، يُعاد التحقق من ماي فاتورة قبل تغيير أي شيء.
- **إذا تعذّر الوصول لماي فاتورة** لحظة رجوع العميل، تظهر له رسالة «نتحقق من الدفع» بدل «فشل الدفع» حتى لا يدفع مرتين، والـ Webhook يؤكد الحجز عند عودة الخدمة.
- **وصول الإشعار والرجوع في نفس اللحظة آمن**: يُسجَّل الدفع مرة واحدة ويرى الطرفان النجاح.
- دفعة تصل لحجز ملغي تُسجَّل وتظهر للمدير لاستردادها، ولا يرجع الحجز فعّالًا.
- لا يمكن للمدير وضع حالة «تم الدفع» يدويًا. الاسترداد يتم من بوابة ماي فاتورة.

## النشر على الإنترنت

### الخيار ١: Vercel + قاعدة بيانات Neon (الأسهل، مجاني للتجربة)

1. ادخل vercel.com بحساب GitHub، واضغط **Add New… ← Project**، واختر المستودع `rihla` ثم **Import**.
2. في **Environment Variables** أضف:
   - `AUTH_SECRET`: نص عشوائي ٣٢ حرفًا أو أكثر
   - `ADMIN_EMAIL` و `ADMIN_PASSWORD`: حساب المدير الأول
   - `CRON_SECRET`: نص عشوائي (للمهمة اليومية)
3. اضغط **Deploy**. أول نشر يفشل لأن قاعدة البيانات غير موجودة بعد، وهذا طبيعي.
4. من صفحة المشروع: **Storage ← Create Database ← Neon ← Create**، ثم **Connect** للمشروع (يضيف `DATABASE_URL` تلقائيًا).
5. **Deployments ← آخر نشر ← ⋯ ← Redeploy**. البناء ينشئ الجداول والوجهات والمدير تلقائيًا (`vercel.json`).
6. رابطك: `https://<اسم المشروع>.vercel.app`، ولوحة التحكم على `/admin`.

اختياري: مفتاح ماي فاتورة (`MYFATOORAH_API_KEY` و `MYFATOORAH_API_BASE`)، وواتساب للأعمال، وبريد SMTP. بدون مفتاح ماي فاتورة يعمل التحويل البنكي فقط. ولربط دومينك: **Settings ← Domains**.

### الخيار ٢: سيرفر خاص (VPS) باستخدام Docker

```bash
cp .env.example .env   # عدّل القيم، وأضف POSTGRES_PASSWORD
docker compose up -d --build
docker compose exec app npm run db:migrate
docker compose exec app npm run db:seed
```

ضع أمامه Nginx أو Caddy لشهادة HTTPS (الـ Webhook من ماي فاتورة يتطلب HTTPS).

## ملاحظة عن إصدار واجهة ماي فاتورة

الربط يستخدم الإصدار v2 (SendPayment و GetPaymentStatus) لأنه الموثّق بالكامل ويعرض للعميل كل طرق الدفع في صفحة واحدة.
ماي فاتورة أصدرت أيضًا v3. كل التعامل مع البوابة موجود في ملف واحد `src/lib/myfatoorah.ts`، فالانتقال لاحقًا يقتصر عليه.
